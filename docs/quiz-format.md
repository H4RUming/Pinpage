# 퀴즈 파일 형식

실험 세션의 사전 퀴즈, 체크포인트 퀴즈, 최종 시험, 재시험은 진행자가 만든 JSON 파일 하나로 불러옵니다.
두 조건(도구 / 대조)이 같은 문제를 풀어야 하므로 AI가 만들지 않고, 채점도 AI 없이 코드로만 합니다.

예시: [Examples/quiz-example.json](../Examples/quiz-example.json)

## 전체 구조

```json
{
  "format": "pinpage-quiz",
  "formatVersion": 1,
  "id": "os-week3",
  "title": "운영체제 3주차",
  "quizzes": [
    { "kind": "pre", "questions": [ ... ] },
    { "kind": "checkpoint", "title": "체크포인트 퀴즈", "questions": [ ... ] },
    { "kind": "final", "questions": [ ... ] },
    { "kind": "retest", "questions": [ ... ] }
  ]
}
```

| 항목 | 필수 | 설명 |
|---|---|---|
| `format` | 예 | 항상 `"pinpage-quiz"` |
| `formatVersion` | 예 | 지금은 `1` |
| `id` | 예 | 퀴즈 세트 식별자. 로그에 남습니다 |
| `title` | 예 | 세션 시작 화면에 보이는 이름 |
| `quizzes` | 예 | 퀴즈 목록. 종류(`kind`)마다 하나씩 |

## 퀴즈

| 항목 | 필수 | 설명 |
|---|---|---|
| `kind` | 예 | `pre`(사전 퀴즈), `checkpoint`(체크포인트 퀴즈), `final`(최종 시험), `retest`(재시험) |
| `title` | 아니요 | 화면 제목. 없으면 종류 이름 |
| `questions` | 예 | 문제 목록 (1개 이상) |

필요한 종류만 넣어도 됩니다.

- 학습 세션에는 `checkpoint`가 있어야 합니다. `pre`가 있으면 학습 전에 먼저 풉니다. 없으면 바로 학습을 시작하고, 도구 조건의 연습 문제 난이도는 설정값을 씁니다.
- 최종 시험 세션에는 `final`, 재시험 세션에는 `retest`가 있어야 합니다.

## 문제

공통 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| `id` | 예 | 같은 퀴즈 안에서 겹치지 않는 식별자. 로그에 문제별 응답이 이 id로 남습니다 |
| `type` | 예 | `multiple_choice`(객관식) 또는 `short_answer`(단답형) |
| `prompt` | 예 | 문제 문구 |
| `points` | 아니요 | 배점. 1 이상의 정수, 없으면 1 |
| `source` | 아니요 | 참고용 메모(근거 위치 등). 앱은 쓰지 않습니다 |

객관식 (`multiple_choice`)

| 항목 | 필수 | 설명 |
|---|---|---|
| `choices` | 예 | 보기 2~10개. 같은 보기를 두 번 쓸 수 없습니다. 보기 순서는 섞지 않고 모든 참가자에게 같게 보입니다 |
| `answer` | 예 | 정답 번호. **1부터** 셉니다 (`"answer": 2`는 두 번째 보기) |

```json
{
  "id": "cp-1",
  "type": "multiple_choice",
  "prompt": "너비 우선 탐색(BFS)을 구현할 때 주로 쓰는 자료구조는?",
  "choices": ["스택", "큐", "힙", "해시 테이블"],
  "answer": 2
}
```

단답형 (`short_answer`)

| 항목 | 필수 | 설명 |
|---|---|---|
| `answers` | 예 | 인정할 정답 목록. 하나라도 같으면 정답 |

채점할 때 공백, 대소문자, 문장부호, 전각·반각 차이는 무시하고 글자와 숫자만 비교합니다.
`"너비 우선 탐색"`을 넣으면 `너비우선탐색`, `너비 우선 탐색.`도 정답입니다.
뜻이 같아도 글자가 다르면 틀림이므로 한글 표기, 영어 표기, 약어를 모두 넣으세요.

```json
{
  "id": "cp-2",
  "type": "short_answer",
  "prompt": "임계 구역을 한 번에 한 스레드만 들어가도록 보호하는 잠금 장치를 무엇이라고 하는가?",
  "answers": ["뮤텍스", "mutex", "상호 배제 잠금"]
}
```

## 채점과 통과

- 점수 = 맞힌 문제의 배점 합 ÷ 전체 배점 합
- 통과 기준은 설정 탭의 "퀴즈 통과 기준"(기본 80%)입니다. 기준과 정확히 같으면 통과합니다(5문제 중 4문제 = 80% → 통과).
- 답하지 않은 문제는 틀림으로 채점하고, 로그에는 응답 없음으로 남습니다.
- 체크포인트 퀴즈는 총점과 통과 여부만 보여주고, 어느 문제를 틀렸는지와 정답은 보여주지 않습니다. 떨어지면 다시 학습한 뒤 횟수 제한 없이 재응시합니다(같은 문제).
- 최종 시험·재시험은 한 번만 응시합니다.
- 사전 퀴즈 점수는 참가자에게 보여주지 않습니다. 도구 조건에서는 이 점수로 연습 문제 난이도를 정합니다(설정의 "사전 퀴즈: 기초 / 심화" 기준, 기본: 40% 미만 기초, 75% 이상 심화, 그 사이 보통).

## 사전 퀴즈를 AI로 만들기 (진행자)

학습 세트 화면의 ⋯ 메뉴 → **사전 퀴즈 만들기…**

1. 문제 수와 유형을 고르고 [만들기]를 누르면 세트의 자료에서 고르게 떨어진 위치를 골라 AI가 temperature 0으로 문제를 만듭니다. 난이도는 1·2·3을 번갈아 냅니다.
2. 객관식은 같은 모델이 자료만 보고 직접 풀어 정답 번호를 검증하고, 맞지 않으면 버립니다.
3. 목록에서 정답과 근거를 확인하고, 빼고 싶은 문제의 체크를 풉니다.
4. [저장] → 새 파일로 저장하거나, 체크포인트·최종 시험을 이미 써 둔 퀴즈 파일에 넣습니다(그 파일의 `pre`만 바뀝니다).
5. 문구를 고치려면 저장한 JSON을 텍스트 편집기로 고칩니다. 단답형은 인정할 표기가 충분한지 꼭 확인하세요.

참가자 앱에서 매번 만들지 않는 이유: 같은 요청을 temperature 0, 같은 seed로 보내도 서버가 여러 요청을 함께 처리하면 결과가 달라질 수 있습니다(실서버에서 동시 요청 8개 중 6가지가 서로 다른 결과). 한 번 만든 파일을 모두에게 나눠 줘야 모든 참가자가 같은 문제를 풉니다.

## 불러오기와 확인

- 세션 시작 화면의 [불러오기…]로 파일을 고르면 형식을 검사합니다. 고칠 곳이 있으면 `체크포인트 퀴즈 3번 문제 (id: cp-3): 정답 번호 5가 보기 수(4)를 벗어납니다`처럼 위치를 알려줍니다.
- 불러온 내용은 앱 DB에 저장하므로 원본 파일을 옮기거나 지워도 진행 중인 세션은 이어집니다.
- 파일 내용의 SHA-256이 세션 시작 화면과 이벤트 로그(`session_started`, `quiz_started`)에 남습니다. 모든 참가자의 값이 같은지 확인하세요. 파일을 한 글자라도 고치면 값이 바뀝니다.
- 같은 내용의 파일을 다시 불러오면 새로 저장하지 않습니다.

## 로그에 남는 내용

| 이벤트 | 내용 |
|---|---|
| `session_started` | 참가자 ID, 조건, 세션 종류, 학습 세트와 PDF별 SHA-256, 퀴즈 파일(id, 제목, SHA-256, 종류별 문제 수), 통과 기준, 모델, 설정 스냅샷(API 키 제외), 서버 주소를 뺀 설정 해시, 템플릿 지문 |
| `quiz_started` | 퀴즈 종류, 몇 번째 응시인지, 문제 id 목록, 전체 배점, 다시 열어 이어 푸는지 |
| `quiz_submitted` | 문제별 응답·정답 여부·배점·득점, 총점, 비율, 통과 여부, 답하지 않은 문제 수, 응시에 걸린 시간 |
| `practice_difficulty_set` | 도구 조건의 연습 문제 난이도와 근거(사전 퀴즈 비율 또는 설정값) |
| `session_resumed` | 다시 열었을 때 꺼져 있던 시간, 지난번에 정상 종료했는지, 그때까지의 단계별 시간 |
| `session_ended` | 종료 이유(통과 / 제출 / 중단), 단계별 시간, 통과까지 걸린 시간(사전 퀴즈 제외), 체크포인트 응시 횟수 |
| `document_opened`, `document_searched` | 자료 뷰어에서 연 문서(목록 또는 근거 위치), 문서 안 찾기 검색어와 찾은 개수 |

내보내기 파일(세션 요약 CSV, 문항별 응답 CSV)의 형식은 [log-format.md](log-format.md)를 보세요.
