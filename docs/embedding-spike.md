# 임베딩 모델 앱 내장 검증 (embeddinggemma-2)

- 날짜: 2026-10-28
- 기기: Apple M2, 24GB, macOS 27.0.1
- 모델: `google/embeddinggemma-2` (텍스트만 사용, 768차원)
- 스크립트: [Tools/embedding_spike](../Tools/embedding_spike)

## 방법

- 테스트 자료: 한국어 강의 자료 문단 48개, 파이썬 코드 조각 8개, 정답이 정해진 질문 24개
  - 일부 질문은 문단과 코드 둘 다 정답
  - 순위가 쉽게 바뀌도록 비슷한 주제의 문단을 일부러 섞음
- 작업 프롬프트: 질문 앞에 `task: search result | query: `, 문서 앞에 `title: {제목} | text: `
- 기준값: PyTorch CPU float32 (sentence-transformers)
- 비교 지표
  - 코사인: 같은 문장의 벡터가 기준값과 얼마나 같은지
  - top5 겹침: 상위 5개 결과 중 기준값과 같은 비율
  - 순서 동일: 상위 5개가 순서까지 기준값과 같은 질문의 비율
  - top1 동일: 1위가 기준값과 같은 질문의 비율
  - hit@5: 정답이 하나라도 상위 5개 안에 든 질문의 비율
  - recall@5: 정답 근거 중 상위 5개 안에 든 비율

### Neural Engine에서 순위가 달라진 경우 (24개 질문 중 3개)

세 경우 모두 5위만 바뀌었고, 기준값에서 5위와 6위의 점수 차이가 0.0005 이하로 거의 동점이었다.
1위와 정답 근거는 하나도 바뀌지 않았다.

| 질문 | 기준값 5위 → Neural Engine 5위 | 기준값 5·6위 점수 차이 |
|---|---|---|
| 재귀 함수가 멈추지 않고 에러 나는 이유 | p44 → p07 | 0.0005 |
| self가 뭘 의미하는지 모르겠어 | c06 → c03 | 0.0004 |
| 한글 파일 읽을 때 디코딩 에러가 나 | p48 → p21 | 0.0001 |

## 실행 방식별 판단

| 방식 | 결과 | 앱에 쓸 수 있는지 |
|---|---|---|
| Core ML | Neural Engine 100% 배치, GPU 결과는 기준값과 같음 | **가능.** OS 기본 기능이라 외부 라이브러리 없음 |
| llama.cpp (GGUF) | ggml-org가 GGUF 배포. 실행 파일 실행이 권한 검사에서 막혀 측정 못 함 | 가능하지만 C++ 라이브러리를 앱에 넣어야 함 |
| MLX | mlx-vlm 특정 git 커밋에서만 동작, Swift 구현 없음 | 지금은 어려움 |

## 앱에 넣을 때 확인할 점

- **최소 OS 버전:** Core ML 모델이 여러 함수를 한 파일에 담은 형식이라 **macOS 15 이상**이 필요하다. 앱의 최소 버전(14)을 올리거나, 함수별로 다시 변환해야 한다.
- **첫 실행 컴파일:** 처음 불러올 때 Neural Engine용 컴파일에 약 70초(M2)가 걸린다. Core ML이 결과를 캐시하므로 한 번만 걸리지만, 실험 전에 미리 끝내야 한다.
- **모델 파일:** 텍스트 모델 271MB, 토큰 표 256MB, 토크나이저 31MB로 총 약 560MB다.
- **입력 처리:** 토크나이저 실행, 토큰 표 조회(bf16 → fp16, √512 곱하기), 길이별 함수 선택(32~512토큰)을 Swift로 구현해야 한다.
- **입력 길이:** 512토큰을 넘으면 잘라야 한다. 청크 800자는 이 범위 안에 든다 (테스트 문서는 최대 111토큰).
- **아직 측정하지 못한 것:** M3에서의 결과. M2와 M3 사이의 차이는 직접 측정해야 알 수 있다.
